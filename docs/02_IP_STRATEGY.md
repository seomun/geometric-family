# 02. 기하학 가족 — IP 전략 (게임 · 블로그 · 쇼츠 · 웹툰)

작성 2026-09-18. 운영자 1인. **AI 가 만들고, 사람이 판단하고 글을 쓴다.**
원칙: 한 화의 원료를 5개 이상으로 쪼개 반복 노출한다. 캐릭터가 코드라 어디에 넣어도 같은 얼굴이다 — 이게 이 IP 의 무기다.

## 1. 한 문장
> 같은 일을 겪는 세 도형 가족. **"당신은 어느 도형인가요?"**

이 한 줄이 모든 채널의 마지막 컷이다. 로고보다 이 질문이 IP 다.

## 2. 역할 분담 — 무엇을 AI 가 하고 무엇을 사람이 하는가
| | AI (Claude Code) | 사람 (작가) |
|---|---|---|
| 원고 | 컷 나누기, 길이 조절, 말풍선 배치 제안 | **원문 집필** (docs/01), 대사 최종 |
| 그림 | characters.js 렌더, 컷 조립, 리스케일, 썸네일 | 표정·구도 OK 판단 |
| 블로그 | 구조·제목 후보 3개·태그·이미지 삽입 | **본문 직접 씀** (AI 티 안 나게) |
| 쇼츠 | 컷 → 9:16 변환, 자막 타이밍 표, 썸네일 | 나레이션 문장, 목소리(TTS 선택) |
| 게임 | 전부 | 선택지 문구 검토 |
| 댓글 운영 | 좋은 사연 후보 추림 | 답글, 외전 채택 |
| 판단 | KPI 표 만들기 | 무엇을 계속할지 |

글은 AI 초안을 쓰지 않는다. AI 는 **뼈대(제목·소제목·들어갈 컷·길이)** 만 준다. 사람이 살을 붙인다.

## 3. 채널과 형식

### 3-1. 웹툰 (본진) — 주 1화
- 자체 페이지(GitHub Pages) `web/epNN.html` 이 원본. 세로 720px, 10~14컷, 마지막은 투표 CTA.
- 동시에 **네이버 도전만화 / 포스타입** 에 같은 컷을 이미지로 올린다(노출용). 댓글은 자체 페이지(giscus)와 플랫폼 양쪽에서 받는다.
- 화당 산출: 컷 PNG 전체(리스케일 가능), 썸네일 1:1, 커버 16:9.

### 3-2. 쇼츠 / 릴스 — 화당 2~3개, 15~25초
세 가지 고정 포맷만 쓴다. 포맷이 고정이어야 AI 가 자동으로 만든다.
| 포맷 | 구조 | 예 (1화) |
|---|---|---|
| **A. 세 창가** | 같은 상황 3컷 연속 → 질문 | 부고 문자 → 네모/세모/동그라미 창가 → "당신은?" |
| **B. 한 마디** | 대사 1줄 클로즈업 + 반응 2컷 | "넌 얼마나 했냐?" / "그런 거 알아 뭐하게" |
| **C. 어느 도형?** | 상황 제시 → 3지선다 → 정답 없음 | "부의금, 당신은 얼마?" |
- 마지막 컷은 항상 동일: 세 도형 + "당신은 어느 도형인가요?" + 다음 화 예고.
- 제작: `tools/shorts.py`(예정) 가 컷 SVG 를 1080×1920 PNG 로 뽑고 자막 타이밍 표를 만든다. 영상 합치기는 CapCut/ffmpeg. 나레이션은 사람 목소리 또는 TTS 중 택1 — **한 번 정하면 안 바꾼다**(목소리도 IP).

### 3-3. 블로그 — 화당 1개
- 형식 두 가지만: **「N화 뒷이야기」**(왜 이 장면을 넣었나, 실제 경험) / **「1인 제작기」**(SVG 캐릭터로 웹툰 만들기 — 개발자·창작자 유입).
- AI 가 주는 것: 제목 후보 3, 소제목, 삽입할 컷 3장, 800~1200자 가이드. 본문은 사람.
- 플랫폼: 네이버 블로그(검색) + 브런치(감성 독자) 동일 글. 게시 후 URL 을 `content/blog/epNN.md` 에 기록.

### 3-4. 게임 (Dress Story 엔진 재사용) — 3화 이후
- **「어느 도형 테스트」**: 단일 HTML, 상황 10개 × 3지선다 → 결과 = 네모/세모/동그라미 + 세부 타입(네모 아빠형, 세모 아내형…). 공유 카드 이미지 자동 생성. 쇼츠 C 포맷과 같은 데이터.
- 왜: 드레스업 엔진(상황 → 선택 → 장면 → 결과)이 그대로다. 데이터만 `data/quiz.json`. 성인 타깃이라 광고 가능.
- 나중: 「기하학 가족 — 우리 집 청소」 같은 미니게임은 반응 본 뒤.

### 3-5. 굿즈 / 스티커 — 반응 후
캐릭터가 벡터라 스티커·이모티콘(카카오)·티셔츠가 즉시 가능. 이모티콘은 심사 기준(24종 표정)이 있어 감정 시트를 확장하면 된다. P4 이후.

## 3-6. 이야기 수집 → 빠른 생산 파이프라인 (2026-09-18 추가)
```
python tools/collect_stories.py   (주 1회, 월요일)
  → content/seeds/inbox/YYYY-MM-DD.md : 국내외 RSS(레딧 가족·부부·직장 / 구글뉴스 사연) 에서 키워드 점수로 후보 100건, TOP 5 에 "네모라면/세모라면/동그라미라면" 빈칸
  → 사람: TOP 5 중 1개 고르고 세 줄 채움 (원문 인용 금지, 상황만 차용)
  → AI: 6컷 축약 웹툰 조립 + 쇼츠 C 포맷 자동
  → 사람: 「네모의 글」 장문 1편 (웹툰 아래 "더 읽기" 링크)
```
소스 추가는 `tools/sources.json` (RSS 주소만). 죽은 소스는 로그에 [skip] 으로 남고 건너뛴다.

### 형식 2안 — 「6컷 + 네모의 글」 (아이디어, 3화부터 시험)
- 웹툰은 **6컷 이내로 축약**(읽는 부담 최소), 마지막 컷 아래에 "네모의 글 읽기 →" 링크.
- 장문은 블로그(네모)에. 같은 사건을 컷은 세 가족 반응으로, 글은 네모 1인칭 속마음으로.
- 장점: 웹툰 제작 시간 절반, 블로그 유입 자동, 짧은 것(쇼츠·컷)과 긴 것(글)이 서로를 밀어줌.
- 판정: 3~4화를 이 형식으로 내고 투표 클릭률·블로그 클릭률을 1~2화(긴 형식)와 비교.

## 4. 주간 리듬 (1인, 주 8시간 가정)
| 요일 | 일 | 담당 |
|---|---|---|
| 월 | 다음 화 원고 초안(사람) → AI 컷 구성 제안 | 사람 2h / AI |
| 화 | 컷 조립·렌더·검토·수정 | AI / 사람 30m |
| 수 | 웹툰 게시(자체 + 플랫폼), 쇼츠 A 게시 | AI 준비 / 사람 30m |
| 목 | 블로그 본문(사람), 쇼츠 B 게시 | 사람 1.5h |
| 금 | 쇼츠 C 게시, 댓글 답글, 외전 후보 추림 | 사람 1h / AI |
| 주말 | 쉼. KPI 표 자동 갱신만 | AI |

## 5. KPI (4주 판정, Starry Village 와 같은 표)
| 지표 | 기하학 가족 | Dress Story |
|---|---|---|
| 노출당 제작비 | 쇼츠 1개당 사람 시간 | 스테이지당 사람 시간 |
| 참여 | 투표 클릭률, 댓글 수, 외전 채택 수 | 다음 스테이지 클릭률 |
| 재방문 | 2화 → 3화 이어 본 비율 | 이어하기 비율 |
| 팬 신호 | "나는 세모다" 류 자기동일시 댓글 | 캐릭터 이름 언급 |
4주 뒤 한쪽에 집중. 둘 다 죽으면 형식(도형 / 드레스업)이 아니라 **채널**을 바꿔 본다.

## 6. 첫 4주 실행
- 1주: 1화 게시(자체+도전만화), 쇼츠 A·B·C 3개, 블로그 「부고 뒷이야기」. giscus 댓글 연결.
- 2주: 2화 「집 청소」. 쇼츠 3. 블로그 「SVG 로 웹툰 만들기」.
- 3주: 3화(소재: 중고차). 「어느 도형 테스트」 게임 베타.
- 4주: 4화(어버이날). 외전 1편(댓글 사연). KPI 판정.

## 7. 하지 않는 것
AI 가 쓴 티 나는 블로그, 캐릭터 그림체 변경, 한 화에 사건 2개, 주 2화, 유료화 논의(4주 전), 다른 도형 추가.
