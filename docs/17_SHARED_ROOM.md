# 17. 공유 룸 「기하학 가족의 집」 — 라인업을 하나로 묶는 차별화 (2026-10-07, 작가 아이디어)

> 작가: "모든 게임에 룸을 꾸미는 아이템을 주자. 5개 게임이 다 다른 걸 주고, 모든 게임은 그 룸과 꾸미기를 공유한다. 게임은 계속 늘릴 수 있다."

## 1. 한 줄
**게임마다 다른 가구 세트를 얻고, 꾸미는 집은 하나다.** 새 게임 = 새 세트 = 집에 새 방이 열린다.

## 2. 왜 차별화인가
| 일반 캐주얼 게임 | 기하학 가족 |
|---|---|
| 게임마다 따로 논다 | **집 하나가 모든 게임을 묶는다** — 게임을 하나 더 깔 이유 |
| 보상 = 숫자·재화 | 보상 = **세계관 소품**(믹스커피·부의 봉투·축구화·돋보기 — 웹툰에 나온 그 물건) |
| 시즌 이벤트가 게임마다 다름 | **웹툰·쇼츠와 같은 시즌**(추석·수능·김장·연말) — 같은 주에 모든 게임에 같은 소품 |
| 캐릭터는 게임 안에만 | 「당신은 어느 도형?」 결과가 **내 집의 문패·내 캐릭터**로 모든 게임에 따라다닌다 |

## 3. 집의 구조
```
기하학 가족의 집 (마을 한 블록)
├── 🟦 네모네 거실    — 북적, 소파·밥상·장난감
├── 🔺 세모네 신혼집  — 여행 사진·커플 컵·캐리어
├── ⚪ 동그라미네 서재 — 책장·바이올린·빈 의자
├── 🧸 아이 방        — 유아 게임 보상 전용
└── 🌳 마당·골목      — 계절 장식(시즌)
```
- 방마다 바닥·벽지·가구 칸. 놓기·돌리기·색 바꾸기. **"세트 완성"**이면 그 방에 짧은 사연 컷(웹툰 한 장면)이 열린다.

## 4. 게임별 세트 (서로 겹치지 않게)
| 게임 | 주는 세트 | 예 |
|---|---|---|
| ① 기하학 가족 놀이터(유아) | **아이 방 세트** | 기차 장난감·잔칫집 미니어처·도깨비 방망이·스티커 벽지 |
| ② 세 가족 식탁(방치형) | **주방·식탁 세트** | 밥솥·김장 김치통·믹스커피·라벨 반찬통·큰 상 |
| ③ 도형 합치기(머지) | **가구·건축 세트** | 도형 블록 소파·세모 지붕 책장·동그라미 창문 |
| ④ 막둥이 색칠북 | **벽지·액자 세트** | 내가 칠한 그림이 **그대로 액자**가 된다(가장 개인적인 아이템) |
| ⑤ 당신은 어느 도형? | **문패·배지·내 캐릭터** | 결과 도형 문패, 성격 배지, 내 아바타 |
| ⑥~ (다음 게임) | 새 방·새 세트 | 확장 슬롯 |
| 웹툰·쇼츠 시즌 | **시즌 세트**(전 게임 공통) | 추석 송편 접시·수능 엿·연말 트리 |

## 5. 기술 — 서버 없이 "집 공유"하는 방법
게임이 **별도 앱**이면 저장 공간이 서로 분리된다. 서버를 두지 않는 원칙을 지키는 선택지:

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A. 같은 서명의 앱끼리 공유 (권장)** | 우리 앱들이 같은 서명 키로 만든 안드로이드 **공유 저장소(서명 보호 ContentProvider)**에 "얻은 아이템 목록"만 쓴다. 어느 앱을 열어도 합친 목록을 읽는다 | 오프라인·서버 없음·개인정보 없음, 설치만 하면 자동 | 안드로이드 전용, 서명 키가 같아야 함(퍼블리셔 계정에서 같은 키로 배포 필요) |
| B. 선물 코드 | 게임에서 짧은 코드(예: 6자리)를 받아 다른 게임에 입력 | 플랫폼 무관, 아주 단순 | 손이 간다 |
| C. 퍼블리셔 계정 SDK | 퍼블리셔의 로그인·클라우드 저장 사용 | 기기 바꿔도 유지, iOS까지 | 퍼블리셔 의존, 개인정보 처리 생김 |
| D. 하나의 큰 앱 | 모든 게임을 한 앱에 | 공유가 제일 쉬움 | 퍼블리셔가 타이틀별로 팔기 어렵고, 유아·성인 정책 충돌 |

→ **A 기본 + B 보조**(D12: **A 는 유아 그룹 ①④ / 성인 그룹 ②③⑤ 로 저장소를 둘로 나눈다**, 그룹 사이는 보호자 잠금 뒤 B 코드로만)(웹·다른 기기). C는 퍼블리셔가 제공하면 그때 연결. 저장하는 건 **아이템 id 목록뿐**(이름·사진·기기 ID 없음) → 개인정보처리방침 변화 없음.

## 6. 유아 앱의 정책 주의 (중요)
- 유아(Kids) 앱 안에서는 **다른 앱 설치를 권하거나 링크하면 안 된다**(광고·외부 이동 금지).
- 그래서 유아 앱에서는 **자기 세트(아이 방)만** 보이고, 다른 게임 세트는 **보호자 잠금(구구단 4지선다 `GF.gate`) 뒤 "가족 집" 화면**에서만 보인다. 그 화면에도 "설치하기" 버튼·링크는 없다(잠긴 실루엣만).
- 다른 게임의 존재 안내는 성인 앱(②③⑤)과 웹툰·쇼츠·블로그에서 한다.

## 7. 공통 구현 (UI 키트와 함께)
- `engine/room/` — 집 화면·방 편집·아이템 데이터(`data/room_items.json`: id·세트·방·크기·색 변형·출처 게임·시즌)
- 모든 앱이 같은 모듈 → **꾸미기 화면이 다섯 게임에서 똑같이 생겼다**(UI 통일의 핵심 화면)
- 아이템 그림: 코드 SVG(`itemAt` 확장) 우선, 대표 가구만 래스터(허브 자산 목록)
- 굿즈 연결: 인기 가구는 실물 미니어처·스티커 후보(백서 §6)

## 8. 순서
1. UI 키트에 `room` 모듈 포함(쇼케이스에 집 화면 한 장)
2. ③ 도형 합치기 슬라이스에 "가구·건축 세트" 10개 + 집 화면 → 허브 QA
3. ①②에 세트 붙이기, ④⑤는 처음부터 포함
4. 앱 간 공유(안 A)는 APK 단계에서 — 같은 서명 키 전제(퍼블리셔와 확인)

## 9. 실물 연결 — 집 속 노트가 진짜 노트로 (작가 아이디어, 2026-10-07)
> 작가: "나중에 우리가 만든 노트 같은 걸 직접 발송해 주면 어떨까."

방향은 좋다 — **디지털 집 ↔ 실물 굿즈**가 이 IP의 가장 큰 차별점이 된다. 다만 "게임 보상으로 실물을 자동 발송"은 세 가지가 걸린다:
1. **주소 수집 = 개인정보** — 유아 앱은 불가, 성인 앱도 방침·보관·파기 절차가 생긴다
2. **게임 결과로 경품 지급** — 국내 게임 법규상 게임 결과에 따른 경품 제공은 제한이 있다 → 출시 전 확인 필요(퍼블리셔 법무)
3. 비용 — 제작비 + 배송 건당 수천 원

그래서 단계로 간다:
| 단계 | 방식 | 걸리는 것 |
|---|---|---|
| **1. 실물 → 디지털 (먼저)** | 굿즈(노트·스티커·키링)를 POD로 **판매**하고, 상품에 **코드 카드**를 넣는다 → 게임에 입력하면 **같은 물건이 집에 생긴다**(실물 노트 = 집 책상 위 노트) | 법·개인정보 문제 없음, 매출이 생긴다, 유아 앱은 보호자 잠금 뒤 코드 입력 |
| **2. 디지털 → 실물 (이벤트)** | 집 세트 완성 화면 캡처로 **블로그·인스타 응모** → 월 몇 명 추첨해 노트 발송 | 게임 밖 이벤트라 주소는 당첨자에게만 받는다(경품 이벤트 고지·제세공과금 기준 확인) |
| 3. 정기 키트 (나중) | 시즌마다 「기하학 가족 문구 키트」 판매 + 그 시즌 집 아이템 코드 | 팬층이 생긴 뒤 |

→ 지금 할 일: 아이템 데이터에 `physical`(실물 짝 상품 id) 칸과 **코드 입력 화면**(보호자 잠금 뒤) 자리만 만들어 둔다.
