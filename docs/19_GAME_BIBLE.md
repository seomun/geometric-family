# 19. 게임 기획 바이블 — 모든 「기하학 가족」 게임의 공통 틀 (2026-10-07)

> 목적: 게임이 몇 개로 늘어도 **같은 IP·같은 구조·같은 손맛**. gf-game 은 이 문서 안에서 **허브 승인 없이 세부 기획을 바로 결정**한다. 허브 승인은 §11 의 항목만.
> 상위 문서: 백서(00) · 공유 룸(17) · 소리(16) · 아트(18) · QA(15) · 규격 `games/SLICE_SPEC.md`

## 0. 최우선 — 작가 결정 (2026-10-07)
> 작가: "전체적인 스토리가 이어지고, 어디서나 내 집을 꾸미는 세계관이 이어지면 되는 거라 **UI랑 사운드 등의 통일성이 제일 중요함**."

게임마다 장르는 달라도 **한 앱을 여러 방으로 나눈 것처럼** 느껴져야 한다. 아래 넷은 게임 고유 기획보다 앞선다(충돌하면 이쪽이 이긴다).
| 이어지는 것 | 한 벌로 쓰는 모듈 | 게임이 하면 안 되는 것 |
|---|---|---|
| **화면(UI)** | `engine/ui-kit` — 타이틀·홈·상단 바·버튼·팝업·결과·설정 | 자체 버튼·자체 팝업·자체 색 |
| **소리** | `data/sounds.json` 하나 + 공용 로더(엔진) — 같은 동작 = 같은 소리(누름 `tap`·정답 `ok`·클리어 `celebrate`·아이템 획득 `star`), 타이틀 = `theme_main` + `logo_sting` | 게임 전용 효과음으로 공통 동작 대체, 로더 복붙 |
| **내 집** | `engine/room` — 모든 게임의 보상 끝이 "집에 놓기" | 게임 안 별도 꾸미기 화면 |
| **이야기** | 공용 **사연 컷 플레이어**(같은 액자·자막·넘김) + **하나의 연대기**(웹툰 회차·계절과 같은 순서) | 게임마다 다른 컷 연출, 웹툰과 어긋나는 시점·설정 |

- 새 게임 착수 전 체크: 위 네 모듈 외의 공통 화면을 새로 만들면 안 된다. 필요한 게 없으면 **엔진에 추가**해 모든 게임이 같이 쓴다.
- 기존 ①②도 이 기준으로 **키트·룸·공용 소리 로더로 이관**한다(새 게임보다 먼저 또는 병행).
- QA 첫 항목 = "다른 게임과 나란히 놓았을 때 같은 집안 물건으로 보이는가"(스크린샷 나란히 + 효과음 id 대조).

## 2. 공통 원칙 (모든 게임, 바꾸지 않는다)
1. **세계관**: 백서 §1 규칙 1~7 — 하나의 사건 세 가족, 행복 먼저, 설명하지 않는 결말, 작은 것도 괜찮다, 숫자는 사실만, 실존 인물·정당·종목·편 가르기 금지.
2. **세 가족 공식이 곧 게임 규칙**: 네모 = 많고 벅참(나눔·바쁨) / 세모 = 극단(큰 한 방·반전, 손해 없이 웃기게) / 동그라미 = 완벽한데 비어 있음(정확·외로움·채우기). 새 게임도 **가족별로 다른 맛**을 하나씩 넣는다.
3. **호칭**: 유아 앱 = 막둥이 시점(아빠·엄마·할머니·세모 이모·세모 삼촌·동그라미 아저씨) / 성인·전연령 앱 = 웹툰 기준(네모 아빠·세모 남편·세모 아내·동그라미 아빠…). 세모네는 **아이가 없다**.
4. **그림**: 캐릭터 = 정본 래스터(시트), 배경·소품·아이콘 = id 슬롯(SVG). 흰 □△○ 단독 기호 금지. 얼굴은 귀엽게, 나이는 소품으로(D5).
5. **압박 없음**: 유아 = 실패·점수·시간제한 없음, 힌트 2단계·적응형. 성인 = 벌·손실·랜덤 뽑기·유료 재화 없음, 오프라인 보상은 접속보다 적게.
6. **개인정보 0**: 서버·계정·분석·광고 SDK 없음. 저장은 기기 안. 수익은 `hooks` 자리만(결정 전 no-op).
7. **유아 정책**: `games/KIDS_COMPLIANCE.md` — 앱 밖 링크·구매·다른 앱 안내는 보호자 잠금 뒤(원칙은 없음).
8. **앱 그룹(D12)**: 유아 그룹 ①④ / 성인 그룹 ②③⑤. 집 저장소는 그룹 안에서만 자동 공유, 그룹 사이는 보호자 잠금 뒤 코드. ③⑤는 만 13세↑ 신고지만 **구현은 Families 수준**(데이터·SDK·외부 링크 0) — 스토어 등록 문구·아이콘에서 유아 대상으로 보이는 표현(“아이용”·“유아”)은 쓰지 않는다.

## 3. 공통 메타 구조 (모든 게임이 같은 뼈대)
```
코어 놀이(게임마다 다름)
   → 보상: ① 게임 고유 진행(별·온기·레벨) ② 도감/스티커 ③ 집 아이템(세트)
   → 집(공유 룸): 다섯 게임 공통 화면, 세트 완성 = 웹툰 한 장면
   → 계절: 웹툰·쇼츠와 같은 주에 같은 시즌 아이템(설·어버이날·추석·수능·김장·연말)
   → 내 도형: ⑤의 결과(네모/세모/동그라미형)가 모든 게임의 문패·캐릭터·말투 힌트로
```
- 보상 표기 단위는 게임마다 달라도 **집 아이템 id 는 공통**(`data/room_items.json`).
- 모든 게임 끝 화면 어딘가에 **"당신은 어느 도형인가요?"** 한 번(유아는 그림 선택, 성인은 질문).

## 4. 공통 화면 흐름 (UI 키트로 똑같이)
```
타이틀(로고·세 가족 등장 ≤3초) → 홈[플레이 · 집 · 도감 · (설정=보호자 잠금)]
  → 선택(지도/레벨판/책장) → 플레이 → 결과(별·아이템 획득 연출) → 다음 / 집으로
```
- 상단 바: 홈 · (진행 수치) · 소리 — 위치·크기·아이콘 전부 키트 그대로.
- 뒤로: 앱 안 ‹ 버튼 + 안드로이드 뒤로(제스처·버튼) 둘 다.
- 전환 0.2s, 암전 금지. 터치 판정 ≥64dp, 폰·탭 가로세로 전부.
- 글자: 유아 = 놀이 UI 글자 없음 + 이야기 자막(24px, 끄기 가능) / 성인 = 18px↑ 고대비.

## 4-1. 공통 진행 구조 + 「이야기 지도」 (작가 2026-10-09, D18)
> 작가: "전체적으로 같은 구조가 이어져야 해. 가벼운 스토리에 이어서 가볍게 플레이를 설명하고, 각 게임별로 상황판(전체 맵, 캔디 크러시 사가의 맵처럼)이 있으면 더 낫지 않을까. 대략적인 스펙을 확정하고 이미지만 교체할 수 있도록."

### 한 장(챕터)의 흐름 — 10앱 모두 똑같이
```
지도에서 장 노드 탭 → ① 이야기 컷 2~4(옛이야기 기, GF.story) → ② 놀이 설명 카드 1장(그림 + 한 줄 + 손가락 시연, 처음 나온 판 종류만)
→ ③ 판들(판 시작·클리어 때 배역 말풍선 한마디) → ④ 장 중간 컷 1~2(승·전, 정해진 판 뒤) → ⑤ 장 끝 컷(결) + 집 아이템
→ ⑥ 지도로 돌아와 다음 장이 열리는 연출(길이 이어지고 아바타가 걸어감)
```
- 설명은 **짧게·한 번**: 성인 = 글 한 줄, 유아 = 글 없이 그림·손가락·음성 슬롯. 설정 「도움말」에서 다시 보기.

### 이야기 지도(사가 맵) 스펙 — 엔진 공용 `GF.saga`
| 요소 | 스펙 | 이미지 교체 슬롯(art_slots) |
|---|---|---|
| 지도 | 세로 스크롤, 아래→위로 올라가는 길. 장마다 한 **구역**(그 옛이야기의 장소: 볏짚집 마을·곰 숲·콩나무 하늘…) | `map:<app>:<ch>:bg`(구역 배경, 세로로 이어지는 타일), `map:<app>:sky` |
| 길 | 구역 배경 위의 점선 길, 노드 좌표는 데이터(구역마다 길 모양 프리셋 3~4종 중 선택) | `map:path_dot` |
| 판 노드 | 동그란 판 번호, 아래 별 0~3, 잠김은 회색, 판 종류는 노드 테두리 색·작은 아이콘 | `map:node`·`map:node_lock`·`map:type:<type>` |
| 장 관문 | 구역 입구에 **이야기 책 노드**(누르면 그 장 컷 다시 보기) | `map:<app>:<ch>:gate` |
| 랜드마크 | 구역마다 그 이야기 상징물 1~2개(벽돌집·꽃신·박·동아줄…) | `map:<app>:<ch>:mark1..2` |
| 보상 상자 | 10판마다 확정 집 아이템 상자(열면 「집에 놓기」) | `map:chest` |
| 내 위치 | 현재 판 노드 위에 **내 아바타**(유아 = 막둥이, 성인 = 내 도형 `Room.me`, 없으면 네모) | 캐릭터 정본 PNG 그대로 |
| 곁가지 | 지도 옆 고정 버튼: 오늘의 한 판·시즌·세 가족 판·순위표·우리 집(키트 아이콘) | 키트 아이콘 |
| 유아 앱 | 노드 크게(≥72dp), 글자 없음(번호 대신 그림 점), 장 = 그림책 표지 | 같은 슬롯 |
| 연출 | 장 클리어 → 길이 그려지며 아바타가 다음 노드로 걸어감(0.8초), 새 구역은 구름이 걷힘 | — |
- **데이터 한 곳**: `data/maps/<app>.json`(구역·길 프리셋·노드 좌표·랜드마크 위치·상자 위치). 그림은 전부 슬롯 id 로만 부르고 지금은 임시 SVG — **아트 패스 때 파일만 바꾸면 끝**.
- 성능: 보이는 구역만 그림(가상 스크롤), 120판도 부드럽게.
- ② 방치형은 판이 없으므로 지도 = 「사연 길」(사연 30편이 노드), ⑤ 어느 도형? = 테스트 노드 지도.

## 5. 진행·스테이지 설계 템플릿
| 구간 | 비율 | 목적 |
|---|---|---|
| 튜토리얼 | 첫 3판 | 손가락 안내, 실패 불가 |
| 도입 | ~10% | 새 규칙 하나씩 |
| 성장 | ~60% | 규칙 조합, 세트 아이템이 자주 나옴 |
| 도전 | ~20% | 같은 규칙의 어려운 변형(별 3개 목표) |
| 쉬어 가기 | 5판마다 1판 | 쉬운 보너스판 — 리듬 |
| 시즌 | 상시 | 해당 달에만 열리는 판·사연 |
- **스테이지는 데이터 + 생성기**: `data/<game>_levels.json` 또는 시드 생성기 + 손으로 고른 고정판. 수량은 §1 목표 이상.
- 난이도 곡선은 시뮬레이터로 검증(`tools/<game>_sim.js`), 별 규칙은 smoke 에 단언.
- 판마다 보상 리듬: 3판마다 작은 보상, 10판마다 집 아이템, 장/구간 끝에 사연 컷.

## 5-1. 놀이 방식 늘리기 (작가 요청 2026-10-07: "게임 방식을 좀 많이 늘릴 수 있도록")
레벨 수만 늘리면 지루하다. **같은 코어에 '판 종류'를 계속 더한다.** 기준:
- 타이틀마다 **판 종류 6개 이상**, 장(챕터)마다 **새 규칙·새 판 종류 1개**를 소개한다(§5 도입 구간 반복).
- 판 종류는 데이터 `type` 필드로 — 생성기·시뮬레이터·smoke 가 종류별로 검증.
- 공통 판 종류(모든 게임, UI 키트로 같은 모양): **오늘의 한 판**(날짜 시드, 하루 1판, 보상 = 집 아이템 조각) · **시즌 판**(웹툰·쇼츠와 같은 주) · **사연 판**(웹툰 회차 하나를 판으로 — 끝에 사연 컷) · **세 가족 판**(같은 판을 네모·세모·동그라미 규칙으로 각각 — "같은 일, 세 가족" 을 놀이로).

| 타이틀 | 판 종류 후보(최소 6) |
|---|---|
| ③ 도형 합치기 | 만들기(목표 단계) · 주문(손님이 원하는 가구 n개) · 짐 치우기(판 위 큰 짐 옆에서 합쳐 없애기) · 좁은 집(판 작고 줄 짧음) · 한 가족만(네모만/세모만/동그라미만) · 이사(판이 한 번 바뀜) · 김장(같은 단계 대량) |
| ① 놀이터 | 모양 맞추기 · 색칠 · 순서(기차) · 소리 따라 하기 · 숨은 도형 찾기 · 짝 맞추기 · 그림책 고르기 — 장마다 1개 새로 |
| ② 세 가족 식탁 | 방치 + 식탁 차리기 미니(배치) · 사연 선택지 · 계절 행사 · 손님 맞이 · 장보기(예산) · 세 식탁 한자리 |
| ④ 막둥이 색칠북 | 자유 색칠 · 번호 색칠 · 스티커 장면 · 배경 고르기 · 따라 그리기(선 잇기) · 웹툰 컷 색칠 |
| ⑤ 어느 도형? | 성격 테스트 · 반응(빨리 누르기) · 기억(컷 순서) · 선택(밸런스 질문, 집계 없음) · 그림 고르기 · 가족 맞히기 |

## 5-2. 퀄리티 향상은 매 회차 (허브가 계속 요청)
허브 QA 마다 **"이번에 좋아진 것 3 / 다음에 올릴 것 3"** 을 기록한다(docs/15). 순서: 통일성(§0) → 손맛(집기·스냅·합치기·클리어 연출, 0.2s 반응) → 판 종류 → 연출(사연 컷·집 놓기) → 그림 슬롯 정리(아트 패스 대기).

## 6. 콘텐츠 원천 (웹툰과 한 몸)
- 이야기·사연·대사는 `content/seeds/author/`(작가 원문, 수정 금지) → `content/episodes/EPISODES.md`·`BANK_v2.md` → 게임 각색은 **[제안] 표기**.
- 숫자를 쓰면 출처·시점(`docs/08~12`). 시즌 소재는 `docs/09·10`.
- 새 인물·새 가족 설정이 필요하면 허브에 요청(§11).

## 7. 품질 기준 (QA 가 보는 것)
`games/SLICE_SPEC.md` + 허브 QA(docs/15): ⓪ **통일성(§0 — 나란히 비교, 소리 id 대조)** ① 폰·탭 가로세로 ② 손맛(집기·스냅·정답·클리어 연출) ③ 세계관·호칭 ④ 글자 크기 ⑤ 정책 ⑥ smoke(구간별)·sim ⑦ 실기기 뒤로/홈.

## 8. 소리·그림
- 소리: `data/sounds.json` 슬롯(docs/16). 음악은 5종 완성 후 Suno 일괄 — 지금은 효과음만.
- 그림: id 슬롯 + `assets/_generated/ASSET_LIST.csv`(docs/18) — Recraft 아트 패스 때 한 번에 교체.

## 9. 수익·정책 표기
- 유아 앱 ①④: 무료·광고 없음·결제 없음.
- 성인 그룹 ②③⑤(만 13세↑): `hooks`(purchase·rewardedAd·grant) 자리만. 방식은 작가·퍼블리셔 결정.

## 10. 게임별 1장 기획서 (GDD-1) 양식 — 새 게임은 이것만 채우면 착수
```
# <타이틀> GDD-1
한 줄 / 장르 / 대상 / 앱 분리(유아·성인)
코어 루프(3줄) / 세 가족이 다른 맛(각 1줄)
웹툰 연결(어떤 원고·에피소드) / 집 세트(10~20개 id)
진행 구조(구간표 §5 적용, 총 판 수) / 생성기 방식
화면 목록(키트 화면 + 고유 화면) / 데이터 파일
리스크 3개 / 슬라이스 범위(첫 N판)
```
→ gf-game 은 GDD-1 을 쓰고 **곧바로 슬라이스 착수**. 허브는 QA 때 함께 본다(§11 항목이 없으면 사전 승인 불필요).

## 11. 허브 승인이 필요한 것 (이것만)
1. 새 장르·새 타이틀 추가 / 타이틀 삭제
2. 세계관·호칭·새 인물·가족 설정 변경
3. 정책(유아·개인정보)에 걸리는 기능
4. 수익 방식, 외부 서비스·SDK
5. 작가 원문 문장의 변경(각색 [제안]은 QA 때 확인)
그 외(레벨 구성·난이도·화면 배치·연출·아이템 목록·이름 짓기 등)는 **gf-game 이 결정하고 기록**한다.
