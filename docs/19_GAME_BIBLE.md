# 19. 게임 기획 바이블 — 모든 「기하학 가족」 게임의 공통 틀 (2026-10-07)

> 목적: 게임이 몇 개로 늘어도 **같은 IP·같은 구조·같은 손맛**. gf-game 은 이 문서 안에서 **허브 승인 없이 세부 기획을 바로 결정**한다. 허브 승인은 §11 의 항목만.
> 상위 문서: 백서(00) · 공유 룸(17) · 소리(16) · 아트(18) · QA(15) · 규격 `games/SLICE_SPEC.md`

## 2. 공통 원칙 (모든 게임, 바꾸지 않는다)
1. **세계관**: 백서 §1 규칙 1~7 — 하나의 사건 세 가족, 행복 먼저, 설명하지 않는 결말, 작은 것도 괜찮다, 숫자는 사실만, 실존 인물·정당·종목·편 가르기 금지.
2. **세 가족 공식이 곧 게임 규칙**: 네모 = 많고 벅참(나눔·바쁨) / 세모 = 극단(큰 한 방·반전, 손해 없이 웃기게) / 동그라미 = 완벽한데 비어 있음(정확·외로움·채우기). 새 게임도 **가족별로 다른 맛**을 하나씩 넣는다.
3. **호칭**: 유아 앱 = 막둥이 시점(아빠·엄마·할머니·세모 이모·세모 삼촌·동그라미 아저씨) / 성인·전연령 앱 = 웹툰 기준(네모 아빠·세모 남편·세모 아내·동그라미 아빠…). 세모네는 **아이가 없다**.
4. **그림**: 캐릭터 = 정본 래스터(시트), 배경·소품·아이콘 = id 슬롯(SVG). 흰 □△○ 단독 기호 금지. 얼굴은 귀엽게, 나이는 소품으로(D5).
5. **압박 없음**: 유아 = 실패·점수·시간제한 없음, 힌트 2단계·적응형. 성인 = 벌·손실·랜덤 뽑기·유료 재화 없음, 오프라인 보상은 접속보다 적게.
6. **개인정보 0**: 서버·계정·분석·광고 SDK 없음. 저장은 기기 안. 수익은 `hooks` 자리만(결정 전 no-op).
7. **유아 정책**: `games/KIDS_COMPLIANCE.md` — 앱 밖 링크·구매·다른 앱 안내는 보호자 잠금 뒤(원칙은 없음).
8. **앱 그룹(D12)**: 유아 그룹 ①④ / 성인 그룹 ②③⑤. 집 저장소는 그룹 안에서만 자동 공유, 그룹 사이는 보호자 잠금 뒤 코드. ③⑤는 만 13세↑ 신고지만 **구현은 Families 수준**(데이터·SDK·외부 링크 0) — 스토어 등록 문구·아이콘에서 유아 대상으로 보이는 표현(“아이용”·“유아”)은 쓰지 않는다.

## 3. 공통 메타 구조 (모든 게임이 같은 뼈대)
```
코어 놀이(게임마다 다름)
   → 보상: ① 게임 고유 진행(별·온기·레벨) ② 도감/스티커 ③ 집 아이템(세트)
   → 집(공유 룸): 다섯 게임 공통 화면, 세트 완성 = 웹툰 한 장면
   → 계절: 웹툰·쇼츠와 같은 주에 같은 시즌 아이템(설·어버이날·추석·수능·김장·연말)
   → 내 도형: ⑤의 결과(네모/세모/동그라미형)가 모든 게임의 문패·캐릭터·말투 힌트로
```
- 보상 표기 단위는 게임마다 달라도 **집 아이템 id 는 공통**(`data/room_items.json`).
- 모든 게임 끝 화면 어딘가에 **"당신은 어느 도형인가요?"** 한 번(유아는 그림 선택, 성인은 질문).

## 4. 공통 화면 흐름 (UI 키트로 똑같이)
```
타이틀(로고·세 가족 등장 ≤3초) → 홈[플레이 · 집 · 도감 · (설정=보호자 잠금)]
  → 선택(지도/레벨판/책장) → 플레이 → 결과(별·아이템 획득 연출) → 다음 / 집으로
```
- 상단 바: 홈 · (진행 수치) · 소리 — 위치·크기·아이콘 전부 키트 그대로.
- 뒤로: 앱 안 ‹ 버튼 + 안드로이드 뒤로(제스처·버튼) 둘 다.
- 전환 0.2s, 암전 금지. 터치 판정 ≥64dp, 폰·탭 가로세로 전부.
- 글자: 유아 = 놀이 UI 글자 없음 + 이야기 자막(24px, 끄기 가능) / 성인 = 18px↑ 고대비.

## 5. 진행·스테이지 설계 템플릿
| 구간 | 비율 | 목적 |
|---|---|---|
| 튜토리얼 | 첫 3판 | 손가락 안내, 실패 불가 |
| 도입 | ~10% | 새 규칙 하나씩 |
| 성장 | ~60% | 규칙 조합, 세트 아이템이 자주 나옴 |
| 도전 | ~20% | 같은 규칙의 어려운 변형(별 3개 목표) |
| 쉬어 가기 | 5판마다 1판 | 쉬운 보너스판 — 리듬 |
| 시즌 | 상시 | 해당 달에만 열리는 판·사연 |
- **스테이지는 데이터 + 생성기**: `data/<game>_levels.json` 또는 시드 생성기 + 손으로 고른 고정판. 수량은 §1 목표 이상.
- 난이도 곡선은 시뮬레이터로 검증(`tools/<game>_sim.js`), 별 규칙은 smoke 에 단언.
- 판마다 보상 리듬: 3판마다 작은 보상, 10판마다 집 아이템, 장/구간 끝에 사연 컷.

## 6. 콘텐츠 원천 (웹툰과 한 몸)
- 이야기·사연·대사는 `content/seeds/author/`(작가 원문, 수정 금지) → `content/episodes/EPISODES.md`·`BANK_v2.md` → 게임 각색은 **[제안] 표기**.
- 숫자를 쓰면 출처·시점(`docs/08~12`). 시즌 소재는 `docs/09·10`.
- 새 인물·새 가족 설정이 필요하면 허브에 요청(§11).

## 7. 품질 기준 (QA 가 보는 것)
`games/SLICE_SPEC.md` + 허브 QA(docs/15): ① 폰·탭 가로세로 ② 손맛(집기·스냅·정답·클리어 연출) ③ 세계관·호칭 ④ 글자 크기 ⑤ 정책 ⑥ smoke(구간별)·sim ⑦ 실기기 뒤로/홈.

## 8. 소리·그림
- 소리: `data/sounds.json` 슬롯(docs/16). 음악은 5종 완성 후 Suno 일괄 — 지금은 효과음만.
- 그림: id 슬롯 + `assets/_generated/ASSET_LIST.csv`(docs/18) — Recraft 아트 패스 때 한 번에 교체.

## 9. 수익·정책 표기
- 유아 앱 ①④: 무료·광고 없음·결제 없음.
- 성인 그룹 ②③⑤(만 13세↑): `hooks`(purchase·rewardedAd·grant) 자리만. 방식은 작가·퍼블리셔 결정.

## 10. 게임별 1장 기획서 (GDD-1) 양식 — 새 게임은 이것만 채우면 착수
```
# <타이틀> GDD-1
한 줄 / 장르 / 대상 / 앱 분리(유아·성인)
코어 루프(3줄) / 세 가족이 다른 맛(각 1줄)
웹툰 연결(어떤 원고·에피소드) / 집 세트(10~20개 id)
진행 구조(구간표 §5 적용, 총 판 수) / 생성기 방식
화면 목록(키트 화면 + 고유 화면) / 데이터 파일
리스크 3개 / 슬라이스 범위(첫 N판)
```
→ gf-game 은 GDD-1 을 쓰고 **곧바로 슬라이스 착수**. 허브는 QA 때 함께 본다(§11 항목이 없으면 사전 승인 불필요).

## 11. 허브 승인이 필요한 것 (이것만)
1. 새 장르·새 타이틀 추가 / 타이틀 삭제
2. 세계관·호칭·새 인물·가족 설정 변경
3. 정책(유아·개인정보)에 걸리는 기능
4. 수익 방식, 외부 서비스·SDK
5. 작가 원문 문장의 변경(각색 [제안]은 QA 때 확인)
그 외(레벨 구성·난이도·화면 배치·연출·아이템 목록·이름 짓기 등)는 **gf-game 이 결정하고 기록**한다.

## 12. 현재 타이틀 씨앗 (GDD-1 빠른 출발점)
| 타이틀 | 코어 | 세 가족 맛 | 웹툰 연결 |

| ① 놀이터 3권 | 「막둥이의 사계절」 등 계절 이야기 5장, 새 놀이 5종(1·2권과 겹치지 않게) | 막둥이 시점 | 김장·첫눈·어버이날 |
