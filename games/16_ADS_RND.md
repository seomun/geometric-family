### 구현 (코드)
- 네이티브: `AdsBridge.java`(Google Mobile Ads 24.4.0 + UMP 3.2.0) = `window.GFAds`(isReady·show·banner·info). 성인은 UMP 동의 후 초기화, 유아는 동의 창 없이 비개인화.
- 레이아웃: `MainActivity` 가 `LinearLayout`(WebView + 배너 자리). 배너가 보이면 WebView 가 줄고 `GF.refit()`, 바닥 여백(`--sab`)은 배너가 맡는다.
- ID 주입: `~/.gradle/gradle.properties` 의 `GF_ADMOB_{APP|BANNER|INTERSTITIAL|REWARDED}_<TODDLER|COLOR|TABLES|MERGE|QUIZ|BLOCK|SPOT|TILE|SORT|DAY>`. **없으면 구글 공식 테스트 ID**(앱 `ca-app-pub-3940256099942544~3347511713`, 배너 `…/9214589741`, 전면 `…/1033173712`, 보상형 `…/5224354917`). 테스트 ID 빌드는 `BuildConfig.GF_AD_TEST=true`(에뮬레이터를 테스트 기기로 등록). **테스트 ID 로 스토어에 올리면 안 된다.**
- JS: `GF.ads`(`engine/ads.js`) `live()`·`banner()`·`interstitial()`·`noteLevelDone(LV)`·`noteStory()`, `GF.onScreen` 훅, UK.result 가 결과 닫기(다음·처음으로·다시) 직후에 전면을 붙인다. 빈도·위치 규칙은 JS 가 정하고 네이티브는 요청대로 보여 주기만.
- 시험: `tools/ads_rules.js`(?ads=1 JS 테스트 광고: 규칙·배너 화면·유아 차단), `tools/ads_shots.js`(보상형 자리), 에뮬레이터(3GB↑): 테스트 광고 3종·`aapt dump permissions`(유아 AD_ID 없음).

### 작가가 할 일 (D19)
1. AdMob 가입(구글 계정) · 앱 10개 등록 → 광고 단위 ID(성인 7앱 × 배너·전면·보상형, 유아 3앱 × 배너) → `gradle.properties` 에 위 키로.
2. 유아 3앱은 AdMob 에서 「어린이 대상」으로 지정 · 광고 단위 가족용. 성인 7앱은 차단 카테고리(사행성·정치·주류) · 최대 등급 PG.
3. `app-ads.txt` 를 올릴 개발자 웹사이트 도메인(루트) 결정.
4. Play Console: 광고 포함 「예」, `store/DATA_SAFETY_ads_ko.md`.
5. 유아 앱의 배너 클릭 → 앱 밖 이동은 SDK 기본 동작(막을 수 없음, 배너를 홈·지도 하단에만 둬서 놀이 중 노출을 피함). Families 심사에서 문제 시 배너만 끄는 옵션(`GF.ads.config.banner=false`)이 있다.

## 1. 유아 그룹 ①④⑩ — 광고를 붙이지 않는 이유와 대안
- Families 정책: 아동만 대상이면 **Google Play Families 자체인증 광고 SDK 버전만** 사용, 개인 맞춤·리마케팅 금지, **앱 시작 직후 전면광고 금지**, 광고 내용은 아동에 적합해야 하며, **AD_ID 권한을 요청하면 안 됨**(API 33↑), 기기 식별자 전송 금지 [확인: Play 정책 센터 Families].
- 우리 현황: 권한 0·SDK 0·외부 링크 0·「광고·결제 없음」이 스토어 문구(KIDS_COMPLIANCE). 광고를 넣으면 이 전부(데이터 안전 양식·방침·심사)가 바뀌고 브랜드 약속이 깨진다. **유아 앱 광고는 비권장.**
- 수익 대안 비교
| 방식 | 장점 | 단점/조건 | 판단 |
|---|---|---|---|
| ⓐ 유료 앱(1회, 예 2,200~3,300원 [추정]) | 가장 단순, 광고·SDK 0, Families 문제 없음 | 설치 장벽 큼, 무료 체험 없음, 판매자 등록·세금(개인/사업자) 확인 필요 [미확인] | 3종 묶음·가족 전체 팩 가격 비교 가능 |
| ⓑ 무료 + 보호자 잠금 뒤 1회 구매 | 체험 후 결정, Families 허용(보호자 확인 필수) | 결제 SDK(Play Billing/Samsung IAP) 추가, 아동 구매 실수 방지 UX 필요 | **권장**(하되 결제는 작가 결정 뒤) |
| ⓒ 구독 | 반복 수익 | 유아 앱엔 부담, 「압박 없음」과 어긋나기 쉬움 | 비권장 |

## 3. 정책·개인정보·연령
- **Data safety(Play)**: 광고 SDK 를 넣으면 「기기 또는 기타 ID」 수집·공유를 신고해야 한다 [추정—Play 양식 일반]. 현재 문구 「수집 없음」이 바뀐다 → 방침(PRIVACY) 갱신 필수. 유아 앱은 변경 없음(광고 SDK 미포함).
- **AD_ID**: 성인 앱에서 광고 SDK 가 쓰면 매니페스트에 `com.google.android.gms.permission.AD_ID` 가 합쳐진다(권한 0 약속이 깨짐). 유아 앱은 **선언 금지** [확인]. flavor 별로 `tools:node="remove"` 로 유아 앱에서 제거 + 성인 앱은 필요시 선언.
- **UMP(동의)**: EEA·영국·스위스·일부 미국 주에서 동의 필요, 앱 시작 시 `requestConsentInfoUpdate()` 호출, `canRequestAds()` 가 true 가 된 뒤에만 광고 요청 [확인: AdMob 문서]. 한국만 배포해도 SDK 흐름에 UMP 를 넣어 두는 것을 권장(해외 설치 가능성).
- **아동 처리**: 혼합 대상(아동+성인) 앱이면 `setTagForChildDirectedTreatment(true)` + `MAX_AD_CONTENT_RATING_G` 와 자체인증 광고 소스만 허용 [확인: AdMob 도움말]. 우리 성인 앱은 「만 13세 이상 일반」 신고(D12). **광고를 켜는 순간 13세 미만 이용 가능성이 심사에서 문제될 수 있음** → 성인 앱 대상 연령을 보수적으로(예: 만 14세↑ 일반 또는 성인) 재검토하는 것을 허브 결정 요청에 올림. 한국은 만 14세 미만 아동 개인정보 처리에 법정대리인 동의가 필요하다는 점(개인정보 보호법)을 법무 검토 사항으로 [미확인—법률 자문 아님].
- **광고 콘텐츠 등급**: 성인 앱도 `setMaxAdContentRating(PG/T)` 로 도박·성인 광고 차단, 광고 범주 차단(사행성·정치·주류) 설정 권장 [추정].

## 4. 수익 규모 감 잡기 (eCPM, 대략)
- 글로벌 모바일 게임 **보상형 eCPM 평균 ≈ $12~15**(2025 보고) [확인: playio 벤치마크 요약], 한국은 안드로이드 보상형 상위권 보고 [확인: Appodeal 요약, 수치 연도 확인 필요], 전면 **$14 안팎(한국 한 달 보고)** [확인]. 배너는 훨씬 낮음(≈ $0.5~2) [추정]. 캐주얼 게임 수익의 보상형 ≈ 39%, 전면 ≈ 44% [확인]. 이 값들은 **광고 단위·시기·채워진 광고주에 크게 달라지는 참고치**이며 보장이 아니다.
- 단순 계산 예시: 일 활성 1,000명, 1인 하루 보상형 1.5회 시청, eCPM $10 ⇒ 1,500 × $10 / 1,000 = **하루 약 $15**(월 약 $450). 우리 앱은 압박이 없어 시청률이 낮을 가능성이 높으므로 **시청률 30%만 가정하면 1/3 수준**. 광고 제거 구매 전환율은 보통 1~3% [추정].
- 결론: 앱 10개를 모두 광고로 먹고살게 하기는 어렵다. **브랜드·IP·굿즈가 본체이고 광고는 보조 수익**.

## 5. 성인 앱 광고 위치 설계 (압박 없음 원칙 안에서)
### 5-1. 보상형(선택) — 1단계
| 앱 | 자리 | 보상 | 보상 없이도 되는가 |
|---|---|---|---|
| ③ 합치기 | 판 안 막힐 때 「한 칸 더」 옆 | 조각 한 번 더 놓기 | 예(힌트는 이미 무료) |
| ⑥ 다른 그림 | 힌트 버튼 | 힌트 +1(하루 한도) | 예(힌트 기본 무제한이면 「정답 하나 짚어 주기」 같은 상위 힌트로 대체) |
| ⑦ 블록 | 자리가 없을 때 「한 번 더」 대신 | 되돌리기 +1 또는 조각 새로 받기 | 예(한 번 더는 무료) |
| ⑧ 정리 | 되돌리기 3번을 다 쓴 뒤 | 되돌리기 +3 | 예(「다시」는 무료) |
| ⑨ 짝 맞추기 | 바구니 칸 하나 더 · 섞기 | +1 | 예 |
| ② 식탁 | 오프라인 온기 수령 | **×2**(선택) | 예(×1 은 그냥 수령) |
| ⑤ 어느 도형 | 결과 카드 | 카드 꾸미기 스티커 | 예 |
| 공통 | 「오늘의 한 판」 | 소품 조각 ×2 | 예 |
- 규칙: ① 광고 버튼은 **글자로 「광고 보고 …」를 정직하게** 표기, ② 거절하면 **아무 불이익 없이 닫힘**, ③ 하루 보상형 한도(예: 앱당 5회), ④ 보상은 **재화·확률이 아니라 한 번의 편의**(「뽑기 없음」 준수), ⑤ 광고가 안 불러와지면 버튼을 숨기거나 「지금은 쉬는 중」 대신 **보상을 그냥 지급**.
### 5-2. 전면 — 2단계(기본 꺼짐, 켠다면 아래 상한)
- 노출 시점: **판 클리어 결과 화면을 닫은 직후**(진행 중간·시작 직후 금지), 홈·설정·유아 앱 금지.
- 상한: **4판에 1회 이하**, 직전 광고와 **3분 이상** 간격, **설치 후 첫 세션·첫 10판 없음**, 「오늘의 한 판」·사연 컷 직후·실패 직후 없음, 하루 **최대 6회**, 광고 제거 구매자 0회.
- 건너뛰기 가능 광고 형식만 허용(콘텐츠 등급 G~PG).
- **압박 없음과의 충돌 검토**: 전면은 사용자가 고르지 않은 시청이라 원칙에 가깝지 않다 → **허브·작가 결정 요청**(기본 권고: 하지 않음. 보상형+광고 제거 구매만).

## 6. 보완 수익
- **광고 제거 1회 구매**: 성인 앱별 또는 「성인 7종 한 번에」 번들. 구매하면 전면 0회, 보상형은 **광고 없이 바로 보상**. 가격은 작가 결정(참고: 업계 흔한 범위 ≈ 2,200~5,500원 [추정]).
- **소품 팩**: 「우리 집」 세트(예: 계절 추석·연말, 굿즈 컬래버)를 유료 팩으로. 소품은 **확정 지급**(뽑기 없음), 실물 굿즈 코드와 연결(docs/17).
- **후원/굿즈 연결**: 앱 안에서 외부로 나가는 링크는 유아 앱 금지, 성인 앱은 보호자 잠금과 무관하게 가능하나 「인터넷 연결 안 함」 문구를 바꿔야 함.

## 7. 사업자(법인·개인사업자)가 없을 때의 제약
| 항목 | 개인 | 비고 |
|---|---|---|
| Google Play 개발자 계정 | 개인 계정 가능, 단 **2023-11-13 이후 만든 개인 계정은 비공개 테스트 12명·연속 14일 뒤에 프로덕션 신청** 가능(조직 계정은 면제) [확인: Play 도움말·보도] | 테스트 12명 모집 필요(가족·지인·테스트 그룹) |
| AdMob | **사업자등록 없이도 수익 수령 가능**, 세금 신고는 필수(종합소득세) [확인: 국내 블로그·질의, 법률 자문 아님], 수령에 주소 확인 PIN·세금 정보·결제 계정 필요 [추정] | 연 소득이 커지면 사업자등록 검토 |
| 갤럭시 스토어 | 삼성 계정으로 셀러 등록 [확인], **유료 판매·결제 시 개인/사업자 요건은 이번에 확인 못 함** [미확인] | 셀러 포털 고객센터에 확인 |
| 유료 앱·인앱결제 | Google Play 판매자 프로필 정보 필요, 한국 통신판매업 신고 의무 여부 [미확인] | 광고 제거·소품 팩 판매 전에 확인 |
| 세금 | 광고·판매 수익은 종합소득세 신고(소득 분류 사업/기타는 세무사 상담) | 건강보험 등 영향 가능 |
→ **광고(보상형)와 광고 제거 구매 모두 사업자 없이 시작 가능한 것은 AdMob 광고뿐**으로 보이며, 구매 판매는 판매자 조건 확인 뒤 결정.

## 8. 구조 설계 — `GF.ads` 공용 브리지 (이번에 코드로 넣은 것)
```
GF.ads.config  = { enabled:false, interstitial:false, test:true, adFree:false, dailyCap:5 }
GF.ads.available(kind)            // 'rewarded'|'interstitial' : 네이티브 준비됨 && 켜짐 && 한도 이내
GF.ads.rewarded({placement, onReward, onClose})      // 사용자 눌렀을 때만
GF.ads.interstitial({placement, onClose})            // config.interstitial && 상한 규칙 통과 시에만
GF.ads.reward(placement, grantFn)                    // 「광고 보고 받기」 버튼 한 줄 도우미: 광고제거 구매자는 바로 지급
```
- **네이티브(2단계에서 작성)**: `AdsBridge`(`@JavascriptInterface`) — `isReady(kind)`, `load(kind)`, `show(kind, id)`; 네이티브가 `window.GF_adsEvent(id, 'reward'|'close'|'fail')` 로 결과를 돌려준다. 미디에이션 우선순위는 AdMob 콘솔(워터폴/입찰)에서.
- **테스트 광고**: Google 공개 테스트 광고 단위 ID 를 쓴다(보상형 `ca-app-pub-3940256099942544/5224354917`, 전면 `ca-app-pub-3940256099942544/1033173712`) — 개발 중 실광고 클릭 금지(계정 정지 위험). 지금은 JS 쪽 **테스트 모드**(네이티브 없음): 버튼은 숨겨져 있고, `config.enabled=true`·`test=true` 면 작은 팝업(「테스트 광고」)으로 보상 흐름만 시험.
- **현재 앱 동작**: `enabled=false` 가 기본이라 **사용자 화면은 바뀌지 않는다**. smoke 가 테스트 모드로 「광고 버튼 → 보상 → 닫기 / 거절해도 불이익 없음」 흐름을 단언.
- **앱별 자리 훅**(코드에 이름만 있음, UI 노출은 광고 켠 뒤): ⑥ `hint2`, ⑦ `undo`, ⑧ `undo3`, ⑨ `extra`, ② `offline2x`, 공통 `daily2x`.

## 10. 작가가 할 일 목록 (SDK 연동 전 필요)
1. **결정**: ① 성인 앱 광고를 켜는지(예/아니오) ② 전면 광고 허용 여부(권고: 아니오) ③ 광고 제거 가격·번들 ④ 성인 앱 대상 연령(만 13세↑ 유지 vs 만 14세↑/성인) ⑤ 유아 앱 수익 방식(광고 없음 유지 + 유료/보호자 잠금 구매)
2. **계정**: AdMob 가입(Google 계정), 지급 계정·주소 PIN·세금 정보, Play Console 개발자 계정(개인이면 비공개 테스트 12명 14일), 갤럭시 스토어 셀러 등록
3. **확인(미확인 항목)**: 한국 개인의 유료 판매·인앱결제 요건(통신판매업), 갤럭시 스토어 유료 판매 요건, AdFit 보상형 지원, 만 14세 미만 개인정보 법정대리인 동의 관련 법무 확인
4. **방침**: 개인정보처리방침 URL, 운영자 정보, Data safety 답안 갱신(광고 SDK 포함 앱만)
5. **테스트 사람 12명**(Play 비공개 테스트) 모집
