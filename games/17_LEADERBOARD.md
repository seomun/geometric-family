# 17. 순위표 — 내 기록 · 세 가족 순위표 · Google Play 게임즈 브리지 (허브 결정 D16, 2026-10-08)

> 작가: 「게임에 순위표 만드는 게 어렵나?」 → 「다 지시해」. D15 의 「리더보드 거부」는 이 문서의 범위로 **수정**한다: **서버·계정 없이 기기 안에서만 도는 순위표**는 한다. 실제 온라인 순위(Google Play 게임즈)는 브리지(꺼짐)까지만.
> 대상: 성인 점수형 ③ 합치기(오늘의 한 판) · ⑥ 다른 그림(오늘의 한 판) · ⑦ 블록(**끝없이**·오늘의 한 판) · ⑧ 정리(오늘의 한 판) · ⑨ 짝 맞추기(오늘의 한 판). **유아 ①④⑩ 없음, ⑤(결과형)·②(방치형) 제외**(`tools/rank_smoke.js` 가 단언).
> 원칙: 압박 없음(지면 문구 없음, 순위가 낮아도 불이익 0) · 뽑기 없음 · 서버 없음 · 통일성(키트 시트·큰 글씨).

## 1. 구성 (3층)
| 층 | 내용 | 상태 |
|---|---|---|
| ① 내 기록 | 보드마다 **최고 10개**(점수·날짜) 기기 안 저장. 통계 화면 → 「○○ 순위표」→ 「내 기록」 탭 | ✔ |
| ② **세 가족 순위표**(서버 없음) | 네모 아빠·네모 엄마·세모 남편·세모 아내·동그라미 아빠가 **각자 가족 규칙으로 플레이한 점수** 사이에서 내 자리를 보여 준다. 오늘 / 이번 주 / 내 기록 탭 | ✔ |
| ③ Google Play 게임즈 순위표 | `GF.board.submit/show` 브리지만. **꺼짐(no-op)**, Play 판 flavor 에서만, 끝없이·오늘의 한 판 점수만 | 브리지 ✔, 연결은 작가 계정 뒤 |

## 2. 세 가족 순위표 — 결정적으로 만든다
- **같은 날이면 모두에게 같은 점수**: 점수는 (앱 · 보드 · 날짜 · 사람) 으로 만든 시드에서 결정된다. 기기·시각·실행 횟수와 무관, 뽑기 없음. 계산 결과는 `gf:<앱>:rank` 캐시에 저장(앱을 다시 켜도 같은 값이라는 것을 smoke 가 확인).
- **봇 = 가족 규칙을 쓰는 실제 탐욕 플레이**(각 core 의 `botPlay`): 같은 판을 네모(규칙 0)·세모(규칙 1)·동그라미(규칙 2)로 플레이한다. ⑥ 틀린 그림은 칸 상태가 없는 퍼즐이라 **가족 맛으로 만든 모델**(틀린 탭·힌트 수).
- **맛**:
  - 네모 = 꾸준히 중간: 실수율 ε 0.13(아빠)·0.17(엄마), ⑦ 끝없이는 조각 60~90개쯤에서 마무리.
  - 세모 = 들쭉날쭉: 그날 ε 가 0.01(대박) 또는 0.6(꽝)으로 갈림(50:50), 끝없이는 한계 없음.
  - 동그라미 = 높고 일정하지만 가끔 빈자리: ε 0.03, 그날 쉬는 확률 12%(점수 대신 「쉬는 날」).
  - 14일 시험 결과(평균 네모/세모/동그라미, 표준편차): ⑧ 690/680/954 · sd 154/237/112, ⑥ 672/630/907 · sd 133/267/118, ⑨ 876/544/704 · sd 250/383/193, ⑦ 끝없이 244/250/440 · sd 100/203/219.
- **점수식**(사람과 봇이 같은 식): `효율 = 1000 × par / 행동 수 − 60 × 도구 수 − 150 × (다시 하기 − 1)`, 50~1250 으로 자름.
  | 앱 | par | 행동 수 | 도구 |
  |---|---|---|---|
  | ③ 합치기 | 빔 풀이의 최소 놓은 횟수 | 놓은 횟수 | 되돌리기·힌트 |
  | ⑥ 틀린 그림 | 틀린 곳 수 | 틀린 곳 수 + 틀린 탭 | 힌트 |
  | ⑦ 블록(오늘의 한 판) | 풀이의 최소 조각 수 | 쓴 조각 수 | 되돌리기·힌트 |
  | ⑦ 블록(끝없이) | — | `지운 줄×10 + 한꺼번에 지운 횟수×10 + 쓴 조각 수` | — |
  | ⑧ 정리 | 풀이 최소 수 | 옮긴 횟수 | 되돌리기·칸 더·힌트 |
  | ⑨ 짝 맞추기 | — | `600 + 110 × (바구니 여유 칸의 최솟값)` | 되돌리기·섞기·힌트 |
  「다시」(자리가 없어 한 번 더·다시 누름)를 누른 횟수가 다시 하기로 들어간다. 광고 보상(되돌리기 +N 등)도 도구로 센다.
- **이기면 한 줄, 지면 문구 없이 순위만**: 이긴 상대 중 점수가 가장 높은 한 명을 골라 「오늘은 세모 남편을 이겼어요!」(주간은 「이번 주는 …를 앞서고 있어요!」). 못 이기면 아무 문구도 없다(압박 문구 금지).
- **주간**: 월요일에 새로 시작하는 주간 **최고 점수** 순위(하루 한 번만 잘해도 됨, 출석 압박 없음). 지난주 기록은 **내 기록에만** 남는다.
- **보상**: 주 1회, 이번 주 순위표에서 **1위가 되면 그 앱의 집 소품 1개를 확정 지급**(`GF.extras.cfg.rewardItems` 순서대로, 주마다 한 번만). 1위가 아니어도 불이익 없음.
- **키트**: 시트 하나(`GF.rank.open(보드 id)`), 가족 얼굴 원형 + 나(🙂), 글자 토큰 사용 → **큰 글씨**에서도 잘리지 않음(smoke 단언). 열리는 곳: 결과 화면 「순위표 보기」(오늘의 한 판) · 끝없이 종료 팝업 「순위표」 · 통계 화면.

## 3. 저장 · 결정성 세부
- `gf:<앱>:rank` = `{ top:{보드:[{s,d}]}, day:{보드:{날짜:내 최고}}, claimed:{주:보상 소품}, tries:{…}, cache:{보드:날짜:사람 → 점수|null} }`(캐시는 최대 300항목으로 정리).
- 날짜는 기기의 현지 날짜(yyyymmdd), 요일 회전용 일 번호는 기존 `dayNum()` 과 같은 식. 시험용으로 `GF.rank._today` 를 덮어쓴다.
- **결정성 사고 방지(이번에 발견·수정)**: ⑨·⑥ 생성기가 `sort((a,b)=> … + (rng()-0.5))` 같은 **흔드는 비교 함수 정렬**을 써서, Chrome 의 JS 최적화 단계(해석 → 최적화)가 바뀌면 같은 시드가 다른 판을 만들었다(같은 날 오늘의 한 판이 앱을 켤 때마다 달라질 수 있었음). 일관된 키 1개/피셔-예이츠 셔플로 교체해 8회 연속 호출이 같은 판을 낸다(브라우저 시험). 저장된 120판 데이터는 영향 없음.

## 4. Google Play 게임즈 (실제 온라인 순위) — 설계만
### 4-1. 코드(지금 들어간 것)
- `engine/board.js`: `GF.board = { config:{enabled:false}, ids:{}, available(), submit(보드, 점수), show(보드) }`. `window.GFBoard`(@JavascriptInterface)가 없거나 꺼져 있거나 유아 앱이면 **항상 no-op**. `GF.rank.record` 가 점수 기록 때 `submit` 을 부른다(끝없이·오늘의 한 판만).
- 보드 ID 대응표(작가가 Play Console 에서 만든 뒤 `GF.board.ids` 에 채움): `merge:daily` · `spot:daily` · `block:daily` · `block:endless` · `sort:daily` · `tile:daily` (6개). 순위 방향 = 높을수록 좋음, 형식 = 숫자.
### 4-2. 도입 때 할 구조(작가 계정 뒤)
- **flavor 차원 `store` (play / galaxy)** 를 추가해 **Play 판에만** Play 게임즈 SDK(`play-services-games-v2`)와 `GFBoard` 브리지를 넣는다(갤럭시 스토어 판·유아 앱엔 없음). `GFBoard.submit(id, score)` → `LeaderboardsClient.submitScore`, `show(id)` → 순위표 화면 Intent. 자동 로그인(PGS v2) 실패 시 조용히 로컬 순위표만.
- **조건·한계**: 앱을 처음 열 때 로그인 요구 없음(순위표를 눌렀을 때만). 점수는 기기에서 올리므로 부정 점수를 막을 수 없다(캐주얼 정도로만 신뢰). 오프라인에서는 올리지 않고 건너뜀(대기열 없음 — 서버 없음 원칙).
### 4-3. 정책·문서 변경점(연결하는 순간 필요)
| 항목 | 변경 |
|---|---|
| 권한 | `INTERNET`(+`ACCESS_NETWORK_STATE`) 필요 → 스토어 문구 「인터넷에 연결하지 않음」을 **Play 판 성인 앱만** 수정 |
| Data safety | 「개인 정보(이름·사용자 ID)」·「앱 활동」을 Google(Play 게임즈)과 **공유**한다고 신고 |
| 개인정보처리방침 | Play 게임즈 이용 시 Google 이 처리하는 정보(플레이어 ID·표시 이름·점수) 문단 추가, 이용 거부(로그인 안 함) 방법 |
| 연령 | 성인 앱 「만 13세↑」 유지. Play 게임즈 이용 연령 요건은 **공식 문서로 확인 필요 [미확인]** |
| 광고와의 관계 | 광고 SDK 도입 시 같이 정리(`16_ADS_RND.md` §3) |
### 4-4. 작가가 할 일
1. Play Console 개발자 계정 생성(개인이면 비공개 테스트 12명·14일, `16_ADS_RND.md` §7)
2. Play 게임즈 서비스 프로젝트 설정 + 순위표 **6개** 생성(위 대응표, 큰 점수가 위) → ID 목록을 허브에 전달
3. 앱 서명 키 SHA-1 등록(테스트 키·정식 키 각각), 테스트 계정 추가
4. 방침 URL·Data safety 갱신 승인
5. 연결 후 확인 시나리오: 오늘의 한 판 1회 → 구글 순위표에 점수 표시, 오프라인에서 앱이 멈추지 않음

## 5. 시험 (`tools/rank_smoke.js`, ⑤개 앱 × 단언)
같은 시드 = 같은 점수(캐시 지워도·앱 다시 켜도) · 날짜가 다르면 다름 · 점수 범위·쉬는 날 빈도 · ⑦ 끝없이에서 세모가 네모보다 들쭉날쭉 · 지면 한 줄 없음/이기면 한 줄 · 1위 · 주 1위 소품 한 번만 · 월요일 리셋 & 지난주는 내 기록에만 · 시트 6줄이 화면 안·큰 글씨에서 글자 안 잘림 · **실제 오늘의 한 판을 깨면 점수가 기록되고 결과에 「순위표 보기」** · 통계 화면에 순위표 줄 · 유아·결과형·방치형 앱엔 순위표 없음.
