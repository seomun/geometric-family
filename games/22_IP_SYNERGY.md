> 먼저 이 문서(기획) → 허브 QA → 공통 엔진 구현. 모든 항목의 원칙: **압박 없음 · 뽑기 없음(확정 지급) · 서버 없음 · D12 그룹 분리(유아 ①④⑩ ↔ 성인 ②③⑤⑥⑦⑧⑨ 서로 읽지 않음, 유아↔성인은 보호자 잠금 뒤 가족 코드) · 유아 앱은 앱 밖 안내 없음.** 모든 글은 [제안].

## 0. 지금 이미 있는 IP 자산
- **공유 집**(`Room`): 같은 그룹 앱끼리 집 소품·내 도형(`Room.me`)·문패(`Room.mePlate`)를 같은 기기 안에서 공유 — `ShareStore`(서명 확인) + `GFShare` 브리지. 유아 그룹과 성인 그룹은 키가 다르고 서로 읽지 않는다.
- **단일 배역표**(`tales_cast`): 같은 옛이야기는 어느 앱에서나 같은 배역(같은 세 가족 캐릭터). 같은 이야기가 ③⑥⑦⑧⑨ 와 ①⑩ 에 여러 번 나온다.
- 공통 키트(UK)·소리·`GF.story/GF.tale/GF.saga/GF.ops` — 열 개 앱이 같은 모양.
- **빠진 것**: 앱끼리 *서로를 의식하는* 장치가 없다. 앱 하나만 깔아도, 열 개를 깔아도 보이는 것이 같다. 아래는 그 틈을 메우는 7개 시너지.

## 1. 공통 기반 — 「IP 장부(ledger)」
앱마다 흩어진 진행을 **그룹별 하나의 공유 키**에 얹는다.
- 키: `gf:ip:adult:v1`, `gf:ip:kid:v1`(기존 `gf:house:*` 와 같은 `ShareStore` 규칙으로 확장 — `okKey` 에 두 키 추가, 그룹은 `:kid:` 포함 여부). 용량 상한 200KB 그대로.
- 내용(작게): `{ v:1, cards:{<이야기id>:[0~3 비트]}, stamps:{<앱>:[도장 id…]}, cameos:[카메오 id…], me:{…}, plate:[장식 id…], seen:{<앱>:<마지막 접속 일>} }`
- **병합 규칙**: 집(`Room.merge`)처럼 합집합(비트 OR·배열 합집합), 지우는 동작 없음 → 어느 앱에서 얻어도 사라지지 않고, 충돌 없음.
- 모듈 `GF.ip`(새 `engine/ip.js`): `get/put/note*(…)` + 변경 이벤트(`GF.ip.on('card')`) — 각 기능은 이 모듈만 부르면 된다. 웹판·브라우저(GFShare 없음)에서는 그 앱 localStorage 안에서만 동작(기능은 그대로 시험 가능).
- **가족 코드(유아↔성인)**: 기존 집의 보호자 잠금 6자리 코드 방식을 그대로 확장 — 한쪽 앱에서 「가족 코드 만들기」(보호자 잠금/구구단 뒤) → 코드를 다른 그룹 앱에 넣으면 **장부의 「이야기 카드·도장·카메오」만** 합쳐진다(집 소품은 기존 규칙). 코드는 기기 안 문자열(체크섬, `GF.ops` 백업 코드와 같은 직렬화), 서버 없음.

## 2. 일곱 개 시너지
### ① 이야기 카드 맞추기 — 한 편을 여러 앱에서 모아 완성
- **카드 = 한 이야기의 컷 1장**(기승전결 4컷). 이야기마다 카드 4장(예: 아기돼지 삼형제: 볏짚집·나무집·벽돌집·수프). 이야기 17종(`data/tales.json` 의 id) × 4 = 카드 68장.
- **얻는 법(확정, 우연 없음)**: 그 이야기가 나오는 앱의 장 이야기 컷을 **끝까지 보면 그 컷의 카드가 장부에 기록**(기·승·전·결 = 카드 1~4). 앱마다 같은 이야기가 다른 컷 구성이면 매핑은 `ops.json` 의 `cardMap`(앱:장:beat → 이야기:카드) 한 곳.
  - 같은 카드를 여러 앱에서 모아야만 완성되도록: ③은 기·승만, ⑥은 전·결만 같은 방식으로 **앱별 카드 배분표**를 둔다 → 한 편을 완성하려면 **2~3개 앱을 오가야** 한다(열 개 앱을 깔 이유).
- **완성 보상**: 「우리 집」 특별 소품(이야기 17종 → 특별 소품 17개 = `room_items` 새 세트 `story`). 확정 지급, 그룹 장부 안에서만.
- **UI**: 앨범(`GF.ops.openAlbum`)의 「이야기 카드」 칸을 **4칸 퍼즐 카드**로(얻은 컷만 그림, 없는 컷은 실루엣 + 「○○ 앱에서 만날 수 있어요」 — 성인 앱끼리만 앱 이름 안내, 유아 앱은 이름 없이 그림 아이콘만).
- **유아↔성인**: 그룹이 다르면 카드도 따로 모인다. 가족 코드로 합치면 그 이야기의 카드가 같이 보인다(유아 이야기 = ①⑩, 성인 이야기 = ②③⑤⑥⑦⑧⑨).
- 크기: 중(장부 + 앨범 UI + 배분표 데이터).
### ② 기하학 가족 도장책(패스포트)
- **도장**: 앱마다 최대 5개 — 첫 클리어 · 3장 완료 · 6장 완료 · 끝까지(마지막 장) · 오늘의 한 판(또는 앱 고유 1개). 도장 얼굴은 그 앱 대표 캐릭터.
- **세트 완성**: 앱 안에서 도장 5개 = 「앱 도장」, 앱 도장 N개(성인 7 / 유아 3) 모으면 **문패 장식**(내 도형 문패 `Room.mePlate` 에 반짝 테두리·리본·별 등 `plate` 장식 3종) 확정 지급.
- **성인 앱에만 「다른 기하학 가족 게임」 모음 화면**: 도장책 하단 — 7개 앱의 아이콘·이름·내 도장 수, 같은 기기에 설치된 앱은 「열기」(앱 간 인텐트, `GFShare` 로 설치 여부 감지), 없는 앱은 「스토어에서 보기」(Play 링크, `GFOps.openUrl` 새 브리지 — 외부 이동이므로 성인 앱 한정). 압박 문구·「이거 안 하면…」 금지, 한 줄 소개만.
- **유아 앱**: 도장책은 있지만 **앱 밖 안내·링크 없음**(KIDS_COMPLIANCE §3 유지) — 아이 방의 「도장판」 그림(아이콘만)으로 유아 3앱의 도장을 모아 문패 장식 지급.
- 크기: 중(도장 규칙 데이터 + 도장책 화면 + 모음 화면).
### ③ 내 도형 개인화 확대
- ⑤의 결과(`Room.me` = 가족 f ∈ {nemo, semo, dong} + 세부 s)를 **모든 성인 앱**이 읽는다.
  - **아바타**: 지도 아바타는 이미 `Room.me` 사용(RC6) — 칭호와 말투로 확대.
  - **칭호**: 지도 머리글·결과 화면에 「네모 아빠형 ○○」 같은 한 줄(`meTypes[f].sub[s]`).
  - **말풍선 말투**: `GF.tale.say` 의 한 줄을 가족별 어미 필터로(네모: 그대로 / 세모: 느낌표·가벼운 감탄 / 동그라미: 마침표·정돈) — 데이터 변경 없이 `tone(f, text)` 함수 하나, 번역 표(`GF.t`)에는 영향 없음.
  - **결과 효과음·꽃가루 색**을 내 가족 색으로(네모 주황·세모 분홍·동그라미 남색).
- ⑤를 아직 안 한 사람: 모든 앱에서 「내 도형 알아보기」 한 줄(⑤ 있는 기기에서만 실행, 없으면 스토어 안내는 도장책 모음 화면에서만).
- 크기: 소~중.
### ④ 같은 주 같은 시즌(10앱 동시 이벤트)
- `data/ops.json` 에 `weekThemes: [{from:'2026-10-05', id:'chuseok', title:'송편 한 주', icon:'🥮', webtoon:'ep12'}…]` — 날짜(월요일 시작) 기준으로 **이번 주 주제**가 모든 앱에 같은 이름·아이콘으로 나온다. 앱마다 그 주제에 맞는 시즌 판/도안/테스트를 **이번 주 추천**으로 지도 머리에 한 줄(「이번 주: 송편 한 주 — ⑥ 송편 사진 찾기」).
- **웹툰 연결 자리**: `webtoon` 필드(에피소드 id)를 두고, 성인 앱에서 값이 있으면 「이 주제의 웹툰 보기」 버튼(⑦ 링크 시너지와 같은 경로). 값이 없으면 숨김.
- **T1 원격 설정 대비**: 같은 JSON 을 나중에 `GF.net.remote()`(21번 서버 기획 T1)가 덮어쓰도록 구조 고정. 지금은 번들 값(1년치 52주 기본 표, 4계절·명절 위주).
- **압박 금지**: 이번 주가 지나도 사라지지 않음(달력의 「다시 열기」와 같은 규칙), 남은 시간 표시 없음.
- 크기: 소~중(데이터 + 지도 머리 한 줄 + 앱별 매핑).
### ⑤ 캐릭터 카메오 + 「카메오 도감」
- **카메오**: 한 앱의 판 사이(장 끝 컷 직후·지도 복귀 직후)에 **다른 앱의 배역**이 3초 말풍선으로 잠깐 등장 — 예) ⑦ 블록 3장 끝: 「이삿짐을 든 세모 남편」(③ 합치기의 이사 판 배역), ⑧ 정리: 「액자를 나르는 동그라미 아빠」(⑥), ⑥: 「타일 바구니를 든 네모 엄마」(⑨).
- 데이터 `ops.json.cameos`: `{id, host:'block', after:'e3', who:'husband.joy', prop:'🧳', from:'merge', line:'③에서 이삿짐 나르는 중!'}` — 앱당 6~8개, 총 ~50개. **압박·강요 없이 한 번만**(본 것은 도감에 기록).
- **카메오 도감**: 앨범의 한 탭 — 모은 카메오(얼굴 + 소품 + 어느 앱에서 만났는지), 못 모은 것은 실루엣. 완성도 25/50/100% 마다 확정 소품. 장부(`cameos`)가 그룹 공유라 다른 앱에서 모아도 이어짐.
- **유아 앱**: 같은 구조, 글자 없이 그림만(소품 아이콘 + 얼굴, 음성 슬롯), 앱 이름 안내 없음.
- 크기: 중(오버레이 컴포넌트 + 도감 + 데이터 제작).
### ⑥ 공통 결과 공유 이미지
- 성인 7앱의 결과 화면에 **「공유 카드 저장」** 버튼 — 이미지 한 장(1080×1350): 상단 **「당신은 어느 도형인가요?」**, 가운데 내 도형 캐릭터(`Room.me`) + 이번 결과(별/점수/장 완료), 하단 **기하학 가족 로고**(세 도형 코드 SVG) + 앱 이름. 코드(SVG→canvas→PNG)로 만들고 기존 `GFSave`(MediaStore, 권한 없음)로 저장 — **SDK 없음**. 웹판은 다운로드.
- ⑤는 이미 결과 카드 저장이 있어 같은 렌더러로 통합.
- 로고는 코드 SVG(임시) → 아트 패스 때 슬롯 `brand:logo` 로 교체.
- 크기: 소~중.
### ⑦ 웹툰 보기 링크(성인 전용)
- 성인 앱 설정(「웹툰 보기」 줄)과 이야기 화면(장 끝 컷 뒤 작은 링크)에 **블로그 주소**. `ops.json.webtoonUrl`(비어 있으면 숨김 — 작가가 정하면 채움, 이메일처럼 저장소엔 비워 두고 빌드 때 주입 가능), 네이티브 `GFOps.openUrl`(`ACTION_VIEW`)로 시스템 브라우저. 웹판은 새 탭.
- **유아 앱에는 없다**(Java 에서도 flavor 가드).
- 크기: 소.

## 5. 구현 순서와 수용 기준
1. `GF.ip` 장부 + ShareStore 키 + 가족 코드 → smoke: 병합(합집합·충돌 없음)·그룹 분리·코드 왕복.
2. ⑥ 공유 카드(눈에 보이는 결과 먼저)·⑦ 웹툰 링크(소).
3. ① 카드·② 도장·앨범/도장책 UI.
4. ③ 개인화·④ 같은 주·⑤ 카메오(데이터 제작 포함).
- 수용 기준: ① 두 앱을 오가 카드 4장 완성 → 특별 소품 1개 · 한 번 더 완성해도 중복 지급 없음 ② 도장 5개/앱·세트 → 문패 장식 ③ 유아 앱에서 외부 링크·앱 이름 안내 0 ④ 장부에 서버 호출 0 ⑤ 압박·카운트다운 문구 단언(기존 grep 단언 확대).
